# patterna-sdk

Version 0.2.0 (see `CHANGELOG.md`). Needs engine 0.2 or later, which is the engine in production.

**Install.** The npm name is `patterna-sdk`, and it is not published yet: `npm install
patterna-sdk` returns 404 today. Until it is, build it from the public repository
[payam-h/patterna-sdk](https://github.com/payam-h/patterna-sdk) at tag `v0.2.0`:

```sh
git clone --branch v0.2.0 https://github.com/payam-h/patterna-sdk.git
cd patterna-sdk/typescript && npm ci && npm run build && npm pack   # patterna-sdk-0.2.0.tgz
cd /your/app && npm install /path/to/patterna-sdk/typescript/patterna-sdk-0.2.0.tgz
```

In this monorepo the package is `@patterna/sdk` (private); the release script renames it.

TypeScript client for the Patterna API. One package for three places:

- **a backend** (Node 22+, Bun, Deno, edge runtimes) holding the scoped API keys;
- **a browser or React Native / Expo app** talking to *your* backend proxy, never to Patterna
  with a key;
- **tooling and tests**, with the contract types generated from `contracts/openapi.yaml`.

ESM + CJS, TypeScript strict, zero runtime dependencies. Only `fetch`, `AbortController`,
`setTimeout` and, for signing, WebCrypto. No Node built-ins in the core (eslint enforces it).

## Fifteen-minute tour

```sh
cd packages/sdk-ts
npm ci
npm test          # vitest, mocked fetch, ~0.3 s
npm run check     # tsc --noEmit + eslint + vitest + tsup build
```

| File | What |
|---|---|
| `src/client.ts` | `PatternaClient`: every serve and ingest method, input checks |
| `src/http.ts` | fetch wrapper: timeout, one retry for idempotent calls, typed errors, request ids |
| `src/consent.ts` | the consent gate and the opaque-user-id check |
| `src/queue.ts` | `EventQueue`: bounded, persistent offline outbox |
| `src/fallback.ts` | `withFallback` |
| `src/signing.ts` | canonical JSON and HMAC-SHA256 event signatures |
| `src/generated/types.ts` | generated by `make contracts`; never edit |

## The client

```ts
import { PatternaClient } from "patterna-sdk";

const patterna = new PatternaClient({
  baseUrl: "https://patterna-api.orven.am/v1",
  keys: { serve: process.env.PATTERNA_SERVE_KEY, ingest: process.env.PATTERNA_INGEST_KEY },
  traceId: () => currentTraceId(),   // optional: X-Trace-Id on every call
});
```

| Method | Scope / key | Budget | Retried |
|---|---|---|---|
| `recommend(req)` | serve | 150 ms | never: each call logs an impression |
| `reportInteractions(requestId, interactions)` | serve | 5 s | once |
| `ingestEvents(events)` | ingest | 5 s | once (idempotent on `event_id`) |
| `upsertItems(items)` | ingest | 5 s | once |
| `setItemStatus(kind, id, { status, published_at })` | ingest | 5 s | once |
| `setItemTags(kind, id, tags)` | ingest | 5 s | once |
| `setUserMode(userId, mode)` | admin key if set, else ingest | 5 s | once |
| `setUserProfile(userId, profile)` | admin key if set, else ingest | 5 s | once |
| `deleteUser(userId)` | admin key if set, else ingest | 5 s | once |
| `recommendWithFallback(req, fallback)`, `recommendMany(reqs)` | serve | 150 ms | never |
| `abandon(requestId, reason)` | serve | 5 s | once |
| `deleteItem`, `listItems`, `itemsChangedSince` | ingest | 5 s | once |
| `createSigningSecret` and the admin methods below | admin | 30 s | idempotent ones once |

Budgets are per attempt and can be changed per client (`timeouts: { recommendMs, ingestMs,
adminMs }`) or per call (`{ timeoutMs, signal }`). The single retry fires on 5xx and network
errors only, after `retryDelayMs` (100 ms); timeouts are not retried because the budget is
already spent.

Per-call options also take `requestId` (sent as `x-request-id`; minted otherwise), `traceId`
(`x-trace-id`, overriding the client's `traceId()`) and, on `recommend`, `tester: true`
(`x-patterna-tester: 1`).

### Deadlines, request ids and abandonment

- `recommend` sends `x-deadline-ms`: 120 ms by default
  (`timeouts.recommendDeadlineMs`, always below `recommendMs`; the engine's own default budget is
  120 ms too), so the engine serves its own
  fallback in time instead of answering after the client gave up. A shorter `timeoutMs` shrinks
  it by the same margin: `timeoutMs: 80` sends 50.
- The client mints the request id, so it knows it even when no slate comes back.
  `recommendWithFallback` uses that: on a timeout, network error, 5xx or unreadable answer it
  sends `POST /recommendations/{id}/abandon` in the background, and the impression
  counts as a client fallback instead of a slate with zero taps. A 4xx (nothing was logged) is not
  abandoned. Failures of that background call go to `onBackgroundError`.

```ts
const r = await patterna.recommendWithFallback(req, () => newestArticleIds(), { traceId });
if (r.source === "patterna") render(r.value.items);
else { render(r.value); log.info({ request_id: r.requestId, code: r.error.code, abandoned: r.abandoned }); }
```

Call `patterna.abandon(requestId)` yourself when a slate arrived but the app showed something
else.

### Several surfaces in one call

`recommendMany([{ request, fallback }, ...])` runs the requests in parallel; each has the same
budget from the same start, so Home's articles and products cost one budget, not two. Each falls
back and is abandoned on its own and is its own impression and ledger row. Use it when the
placements are separate on screen; one surface with mixed `candidate_kinds` gives one list and one
ledger row you cannot split later.

### Interactions: kind, re-sorting and split blocks

- `kind` is required for anything that is not a document. For
  slates this client served, an interaction without `kind` on a community, product, event or tip
  throws `ValidationError` before sending. `interactionFor(slate, itemId, type)` fills `kind` and
  `position`.
- `displayed_position`: when the app re-sorts on the device, keep `position` as the served slot
  and set `displayed_position` to where it was shown.
- `block`: when one slate is split across UI blocks, name the block. A slate of 7
  shown as a top slot plus an end carousel of six: request `slots: 7`, render `items[0]` on top
  and `items.slice(1)` in the carousel, and report with the served positions:

```ts
const s = r.value; // a Slate
const report = [
  interactionFor(s, s.items[0]!.item_id, "seen", { block: "top" })!,                 // position 0
  ...s.items.slice(1).map((it) => interactionFor(s, it.item_id, "seen", { block: "end_carousel" })!), // 1..6
];
await patterna.reportInteractions(s.request_id, report);
```

  Report `seen` for carousel slots only when they scroll into view. One slate keeps one
  impression and one propensity per slot.

### Consent: measured and assignment unit

- `measuredContext(context, analyticsConsent)` sets `measured`: `false` keeps the
  request out of the ledger and the training data; the slate is still ranked and shown.
- `assignment_unit` keeps one non-profiled person in one holdout arm across rotating
  sessions: `assignment_unit: await assignmentUnit(experimentSecret, yourUserId)` on the backend.
  The secret never leaves you; only the 64-hex shape is accepted, so a raw id cannot slip through.
  Same function and test vector in the Go and Python SDKs.

### Catalog reconciliation

```ts
for await (const item of patterna.itemsChangedSince(lastRun)) reconcile(item);
await patterna.deleteItem("community", "community_42");
```

### Admin (admin key)

For CI scripts that keep flow configs in your repository: `listSurfaces`, `getSurface`,
`setSurfaceStatus`, `setSurfaceTesters`, `listFlows`, `getFlow`, `createFlow`, `activateFlow`,
`rollbackFlow`, `planFlow`, `applyFlow(surface, config, { note, activate })`,
`listExperiments`, `startExperiment`, `endExperiment`, `ledger`, `ledgerWeeks`,
`exportLedger`, `exportStatus`, `createSigningSecret`, `rotateSigningSecret`.
`applyFlow` compares configs as canonical JSON: nothing happens when the active version
matches. The Go SDK ships the same as a CLI (`packages/sdk-go/cmd/patterna`).

### Errors

Every failure is a `PatternaError` with `code`, `op`, `status`, `requestId`, `details` and a
`transient` getter. Subclasses: `ApiError` (the API answered; `code` is the API's, e.g.
`pii_rejected`), `TimeoutError`, `NetworkError`, `ConsentError`, `ValidationError`.

`ApiErrorCode` names the codes callers act on; test them with `isApiError(err, code)`:

| Code | Status | In `withFallback` / `recommendWithFallback` |
|---|---|---|
| `no_candidates` | 422 | fallback (nothing eligible) |
| `surface_off` | 409 | fallback (the kill switch) |
| `unknown_surface` | 404 | fallback, but a configuration bug: alert on it |
| `mode_conflict` | 422 | rethrown |
| `pii_rejected` | 422 | rethrown |
| `unknown_request` | 404 | `abandon`, `reportInteractions` |
| `unknown_item` | 404 | catalog calls |

```ts
try {
  await patterna.ingestEvents(batch);
} catch (err) {
  if (err instanceof ApiError) log.warn({ op: err.op, code: err.code, request_id: err.requestId });
  else throw err;
}
```

### Consent gate

- `recommend` throws `ConsentError` (`consent_required`) when `mode` is missing or unknown.
- A `non_profiled` request must carry a `session_id` and no `user_id`; the type forbids it and the
  runtime throws `ConsentError` (`consent_violation`) for untyped callers. Nothing is sent.
- User ids must be the random per-tenant id you mint. Emails and identity-provider subjects
  (`auth0|...`) are refused with `ValidationError` everywhere a user id goes; the id is never put
  in the error message.
- Event `context` accepts only `locale`, `app_version`, `platform`, `hour_bucket`.

### Fallback

```ts
import { withFallback } from "patterna-sdk";

const r = await withFallback(
  () => patterna.recommend({ surface: "home_articles", mode, user_id, context: { locale: "nl" } }),
  () => newestArticleIds(),            // your current query
  { onFallback: (e) => metrics.inc("patterna_fallback", { code: e.code }) },
);
const ids = r.source === "patterna" ? r.value.items.map((i) => i.item_id) : r.value;
```

By default it falls back on any SDK error except `ConsentError`, `ValidationError`,
`pii_rejected` and `mode_conflict`, which are bugs in the caller (a consent bug is a privacy bug)
and are rethrown. Prefer `client.recommendWithFallback`, which also reports abandoned slates. `{ on: "timeout" }`
narrows it to timeouts. Report interactions only when `r.source === "patterna"`.

### Signing

```ts
import { signEvent } from "patterna-sdk";
const signed = await signEvent(event, process.env.PATTERNA_SIGNING_SECRET!);
```

Signature = lowercase hex HMAC-SHA256 over the canonical JSON of the event without `signature`:
keys sorted, no whitespace, `undefined` dropped, U+2028/U+2029 escaped. The key is the UTF-8
bytes of the secret string exactly as the API returned it (`createSigningSecret`, the panel);
never hex-decode it. The Go and Python SDKs produce the same bytes; the suites share the vector
`8baf7299…aac9` with key `test-signing-key`. Sign on a backend; a secret in an app bundle is a
public secret. On React Native without `crypto.subtle`, pass a SubtleCrypto implementation as
the third argument.

## Example: backend proxy

The app never holds a Patterna key. Your backend authenticates the user, swaps the account id for
the Patterna id it minted, applies the user's consent, and forwards. Paths mirror Patterna's so
the same SDK works on both sides.

```ts
import { Hono } from "hono";
import { PatternaClient, withFallback, ValidationError, ConsentError, type Event } from "patterna-sdk";

const patterna = new PatternaClient({
  baseUrl: process.env.PATTERNA_URL!,
  keys: { serve: process.env.PATTERNA_SERVE_KEY, ingest: process.env.PATTERNA_INGEST_KEY },
});
const app = new Hono<{ Variables: { account: Account } }>();
app.use("/patterna/*", requireSession); // sets c.var.account

app.post("/patterna/recommendations", async (c) => {
  const body = await c.req.json();
  const { mode, patternaId } = await consentFor(c.var.account); // your table; missing = non_profiled
  const req =
    mode === "non_profiled"
      ? { surface: body.surface, mode, session_id: body.session_id, context: body.context }
      : { surface: body.surface, mode, user_id: patternaId, context: body.context };
  // fallbackSlate(): your current list as a Slate with `fallback: true` and an empty request_id,
  // so the app renders one shape and skips reporting interactions for it.
  const r = await withFallback(() => patterna.recommend(req), () => fallbackSlate(body.surface));
  return c.json(r.value);
});

app.post("/patterna/events", async (c) => {
  const { events } = (await c.req.json()) as { events: Event[] };
  const { mode, patternaId } = await consentFor(c.var.account);
  // Never trust identity from the client: set it here.
  const owned = events.map((e) =>
    mode === "non_profiled" ? { ...e, user_id: undefined, source: "backend" as const }
                            : { ...e, user_id: patternaId, session_id: undefined, source: "backend" as const });
  try {
    return c.json(await patterna.ingestEvents(owned), 202);
  } catch (err) {
    if (err instanceof ValidationError || err instanceof ConsentError) return c.json({ code: err.code }, 400);
    throw err;
  }
});
```

## Example: Expo app

```ts
import AsyncStorage from "@react-native-async-storage/async-storage";
import "react-native-get-random-values"; // crypto.getRandomValues for newSessionId on Hermes
import { AppState } from "react-native";
import { EventQueue, PatternaClient, newSessionId, withFallback } from "patterna-sdk";

// Talks to YOUR backend proxy above, authenticated as the signed-in user. No Patterna key here.
const patterna = new PatternaClient({
  baseUrl: `${config.apiUrl}/patterna`,
  headers: async () => ({ authorization: `Bearer ${(await getValidTokens())?.accessToken ?? ""}` }),
  timeouts: { recommendMs: 400 }, // a phone round trip to your proxy, which keeps its own 150 ms
});

export const outbox = new EventQueue({
  client: patterna,
  storage: AsyncStorage,         // persist / restore across app launches
  maxSize: 500,
  onDrop: (reason, n) => track("patterna_events_dropped", { reason, n }),
});
let sessionId = newSessionId();  // rotate per launch

export async function onConsentLoaded(mode: "personalized" | "cohort" | "non_profiled") {
  await outbox.setMode(mode);    // nothing is queued before this; non_profiled purges named events
}

AppState.addEventListener("change", (s) => {
  if (s === "active") sessionId = newSessionId();
  else void outbox.flush();      // send before the OS suspends the app
});

export async function homeArticles(fallbackIds: string[]) {
  const r = await withFallback(
    () => patterna.recommend({ surface: "home_articles", mode: "non_profiled", session_id: sessionId, context: { locale: "nl", platform: "ios" } }),
    () => fallbackIds,
  );
  return r;
}

export function seen(requestId: string, itemId: string, position: number) {
  return outbox.enqueue({
    event_id: `${requestId}:${itemId}:seen`,  // idempotency key: one seen per slot
    type: "rec_seen", occurred_at: new Date().toISOString(), source: "sdk",
    session_id: sessionId, request_id: requestId, surface: "home_articles",
    props: { item_id: itemId, position },
  });
}
```

The proxy sets the real identity, so the app sends `session_id` only and stays correct whatever
the user's mode is.

## Status

Built: the full serve and ingest client, the admin methods, client-minted request ids with
abandonment, the server deadline header, trace ids, typed errors with the API code and request
id, per-call timeouts (150 ms / 5 s / 30 s), one retry for idempotent calls, the consent gate in types and at
runtime, opaque-user-id checks, `withFallback`, `EventQueue` (bounded, persistent via an injected
AsyncStorage-shaped store, consent-aware, idempotent restore), HMAC signing with a cross-language
vector, assignment units, session ids. 95 tests with mocked fetch. ESM + CJS + d.ts via tsup.

The request and slate types come from the contract (`src/generated/types.ts`, API 0.2.0), so
`context.control_item_ids` (the caller's own editorial list, the control slate for this page),
`context.member_of` (communities to exclude) and the answer's `control_source` and `fill_count`
are typed. A `shown: false` answer is a normal 200 and is never abandoned: the SDK abandons only
after a timeout, a network error or a 5xx.

Deliberately left out:

- Admin endpoints beyond surfaces, flows, experiments, ledger and the signing secret (keys,
  curation, settings): the panel owns them.
- A circuit breaker: backends that need one use `packages/sdk-go`; in an app `withFallback` and
  the per-call budget are enough.
- No persistent queue for abandonments: they are fire-and-forget promises. In a backend that
  shuts down, a few may be lost; the Go SDK drains its queue on `Close`.
- Not on npm yet: publishing `patterna-sdk` 0.2.0 is pending. Build it from the public
  repository as shown at the top.

Settled since 0.1: the user endpoints (`/users/{id}/mode`, `/users/{id}/profile`,
`DELETE /users/{id}`) accept the ingest key (the SDK uses the admin key when configured, else the
ingest key), and the engine verifies signatures over the canonical form above, as written in
`contracts/events.md`.
